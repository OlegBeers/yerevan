# Ереван на кранах — дизайн v1

Дата: 2026-09-23 · Автор идеи: Олег · Статус: на ревью у Олега

## 1. Что делаем

Живой список крафтового пива в барах и магазинах Еревана на статичной странице и одна тихая сводка новинок в день в Telegram-чат друзей. Бесплатно.

Основа: проект знакомого для Валенсии (github.com/hopandshot/hopsandshot, Python + Playwright + BeautifulSoup, одна страница на GitHub Pages). Автор разрешил взять код. Лицензии в репозитории нет, поэтому в README и подвале сайта указываем, откуда взяли.

**Главное требование: не спамить в чат.** Раздел 7 перечисляет гарантии, каждая закрыта тестом.

**Не делаем в v1 (YAGNI):** подписки и фильтры на человека, команды боту, Telegram Mini App, свой домен, события «вернулось на кран» и «закончилось», автозапуск на Маке, Zovq.

## 2. Ограничения

- **Аудитория:** Telegram-чат друзей (5–30 человек). Олег админ, бот пишет сам. Интерфейс и сводка на русском.
- **Время:** везде Asia/Yerevan (UTC+4, перехода на летнее время нет), через `zoneinfo`. «Сегодня» — дата по Еревану.
- **Репозиторий:** публичный на GitHub. Токен бота и id чатов лежат в GitHub Secrets.
- **Бюджет 0:** GitHub Actions и GitHub Pages бесплатны для публичного репозитория.
- **Untappd:**
  - Правила запрещают автоматический сбор данных. Поэтому жёсткий бюджет 30 страниц Untappd в сутки (раздел 10), только для личного чата, на каждое пиво ссылка на Untappd, и мы готовы к тому, что доступ однажды закроют.
  - untappd.com закрыт проверкой Cloudflare. Headless Chromium с настройками браузера знакомого на GitHub Actions её сейчас проходит (2026-09-23: 4 бара, 310 позиций). Простые HTTP-запросы у одних проектов проходят, у других получали 403. Используем Playwright.
- **Магазины и buy.am** отвечают на простые HTTP-запросы. Проверено с армянского IP, с GitHub ещё нет (раздел 11).

## 3. Архитектура

```
GitHub Actions: cron 17 6 * * * и 17 14 * * * (10:17 и 18:17 по Еревану) + ручной запуск
один job, concurrency: taps (без отмены текущего)
 1. checkout ref: main (вершина ветки, а не SHA события)
 2. python -m taps run
     a. читает places.yaml, corrections.yaml, state.json
     b. по каждому источнику: забрать → «замечено» → проверка здоровья (раздел 10)
     c. слияние с состоянием → события (раздел 6)
     d. пишет site/data.json
     e. если пора слать сводку: отметка «отправлено» в state (раздел 7)
     f. commit + push state.json; push не прошёл → сводку не шлём, выход с ошибкой
     g. если пора: отправка в Telegram; при явном отказе откат отметки + push
 3. публикация site/ на GitHub Pages (upload-pages-artifact + deploy-pages) в том же job
```

- **Минуты cron не круглые.** Расписание GitHub в начале часа ненадёжно: у знакомого срабатывало около 6 из 24 запусков. Два запуска в день страхуют друг друга.
- **Untappd забираем не чаще раза в 20 часов** (раздел 10). Магазины — в каждом прогоне.
- **state.json коммитится каждый прогон.** Он ограниченного размера (раздел 5). Коммиты заодно не дают GitHub отключить расписание после 60 дней без активности.
- **Мак — запасной вариант.** Тот же код запускается командой `python -m taps run`. Протокол тот же: `git pull` в начале, отправка только после удачного push. Есть флаг `--no-digest`. Автозапуск через launchd не в v1.
- **Стек:** Python 3.12, Playwright (Chromium), requests, beautifulsoup4, PyYAML, pytest. Других зависимостей без согласования не добавляем.

**Меню Untappd (4.1).**
- Из `scraper.py` знакомого переносим парсер и настройки браузера:
  - UA Chrome;
  - `--disable-blink-features=AutomationControlled`;
  - stealth-скрипт;
  - паузы.
- Доработки:
  - locale меняем на `en-US`;
  - цена в любой валюте, в том числе «2300.00 AMD»;
  - время обновления меню из `span.updated-time[data-time]`;
  - распознавание Cloudflare из раздела 10.
- Поля: id пива в Untappd, название, пивоварня и её id, стиль, крепость, IBU, рейтинг (`div.caps[data-rating]` в строке меню), объём и цена, вкладка (`menu_id`).

**Чекины (4.2, 4.3).**
- Поля: id чекина, id пива, название, пивоварня, время, подача (Draft / Bottle / Can / пусто, поле бывает пустым), место (id в Untappd).
- **Рейтинга пива, стиля, крепости и IBU у чекина нет.** `.caps[data-rating]` в чекине — личная оценка одного человека, её не используем.
- Для 👀 эти поля берём, только если пиво уже встречалось в любом меню. Страницы пива в v1 не запрашиваем.

**Список сортов пивоварни (4.2, «🏭 новый сорт»).**
- **Включается только после проверки.** На первом ручном прогоне смотрим страницу списка сортов: видны ли без входа все сорта, то есть совпадает ли их число со счётчиком «N Beers» на странице пивоварни. Если нет, список выключен, и 🏭 в v1 не используется.
- **Нагрузка:** 1–2 пивоварни в сутки по кругу.
- **Что считается новым сортом:** id Untappd больше максимального id, уже виденного у этой пивоварни. Незнакомый меньший id запоминается молча.
- **Строки на сайте и пары «место + пиво» не создаёт.** Пополняет только `beers` (для ⭐) и даёт событие 🏭.

**Beer City (4.5).** Проверено 2026-09-23.
- **Частичный прогон, в каждом прогоне.**
  - Запросы: `GET https://www.beer-city.am/en/catalog/sshalcavac-garejur/?sorting=-id&page=1` (бутылки и банки) и то же для `lcnovi-garejur/` (разливное на вынос).
  - Заголовок `X-Requested-With: XMLHttpRequest`; ответ — JSON `{link, products}`, где `products` — HTML карточек, новые сверху.
  - Листаем дальше, пока на странице есть незнакомые номера. Частичный прогон только добавляет новые номера; наличие остальных и `last_count` не трогает.
- **Полный обход** в первом прогоне каждого дня по Еревану, около 26 запросов. Число страниц берём из текста «Page i of N». Время обхода — `sources[…].last_full`.
- **Карточка:**
  - номер `button.wish-list-icon[data-product]`;
  - название `.prod-item-name a`;
  - цена `.new-price .wh-point`;
  - нет в наличии `a.addtocart-but.diss-prod`.
- **Страница товара** (`/en/products/<slug>/`) запрашивается только для новых номеров. С неё берём Brand, объём, крепость, страну, тару. Если она не загрузилась, этот номер в этом прогоне не записывается.
- **Фильтр:** берём только эти две категории и названия, начинающиеся с «Beer» или «Draught beer». Подарочную карту и наборы отсекаем.
- **Разливное здесь — литры на вынос.** Показываем его как товар магазина, не «на кране».

**Yerevan City (4.6).**
- **Список, 1 запрос.** `POST https://apishopv2.yerevan-city.am/api/Product/GetByCategory`, тело `{"categoryId":119,"parentId":119,"count":1000,"page":1}`. Приходит вся категория: около 243 товаров, поля `id`, `name` (по-армянски), `price`, `discountedPrice`, `categoryName`. Признака наличия нет: закончившийся товар просто исчезает из списка.
- **Латинские названия и бренд, 1 запрос.** `POST .../api/Product/Search`, тело `{"search":"գարեջուր","count":500,"page":1,"countries":[],"categories":[],"tags":[],"brands":[],"isDiscounted":false,"sortBy":3}`. Отдаёт `products[]` с `nameEn`, `nameRu`, `brandId` и `searchBrands[]`. Названия брендов в `searchBrands` армянские, поэтому для стоп-листа не годятся.
- **Бренд:** текст в кавычках из `nameEn` (`Beer "Kilikia" 1l` → Kilikia). Если кавычек нет, первое слово `nameEn` после «Beer». Если товара нет в ответе Search, берём «» из армянского названия через таблицу армянских написаний брендов из стоп-листа.
- **Прогон не засчитывается**, если `success != true`, список пустой, в нём меньше `itemCount` позиций или не удался запрос Search.
- **Ссылка на товар:** `https://yerevan-city.am/shop/product-details/{id}`. Фото не копируем: права на контент сайта принадлежат магазину.

**Parma (4.6).**
- **Список.** `GET https://parma.am/en/product/category?slug=beer&available=false&page=N` с `Accept-Encoding: gzip`. Листаем с `page=1`, пока на странице 60 карточек, максимум 8 страниц. Сейчас 224 товара, отсутствующие в наличии идут в конце.
- **Карточка:**
  - код = часть адреса после последнего `_`;
  - название `a.item_name > span`;
  - цена `span.product_price[data-price]`;
  - нет в наличии `div.not_av_content`.
- **Страница товара** (`/en/product/product?slug=…`) запрашивается только для новых кодов. С неё берём производителя и страну, крепость из описания регулярным выражением `(\d+(?:[.,․]\d+)?)\s*%`. Если страница не загрузилась, код в этом прогоне не записывается.
- **Прогон не засчитывается**, если карточек меньше 150.

**Фильтр «интересное пиво» для всех магазинов.**
1. **Выкидываем коктейли, сидры и безалкогольное.** Безалкогольное узнаём по словам cero, zero, 0.0, non-alc, alcohol-free, ոչ ալկ, զերո.
2. **Выкидываем радлеры** по словам вкуса (lemon, grapefruit, radler, կիտրոն, թուրինջ), а не по юридической категории «пивной напиток»: под неё попадают и витбиры.
3. **Оставляем**, если в названии есть стиль: ipa, apa, neipa, stout, porter, tripel, dubbel, quad, sour, gose, kriek, saison, imperial, barley wine, trappist. Даже если бренд массовый.
4. **Выкидываем бренды из `not_craft`.** Бренд сравнивается целым словом, без учёта регистра: «bud» не ловит «Budvar».
5. **Всё остальное оставляем**, в том числе неизвестные бренды.

### v1.1

- **Логотип и «Verified» места (4.1, 4.3).** На странице места (венью), которую и так забираем, из `div.venue-header div.logo` берём: `img[src]` — логотип (или `null`, если блока нет), и наличие `<span>Verified</span>` рядом со ссылкой на фото — признак «Verified» на Untappd. У непроверенных мест этого span нет (вместо него где-то на странице «Unverified»). Кладём в `state.venues[<venue_id>]` при каждом удачном сборе 4.1/4.3.
- **Открытие новых мест по чекинам (4.2, 4.3).** Каждый чекин со страницы пивоварни или места — включая места, которых нет в `places.yaml`, — запоминается в `state.venues[<venue_id>]`: имя, ссылка на Untappd, список чекинов `{id, at}` (без повторов по id, только за последние 30 дней). «Untappd at Home» не считается местом. Пары «место + пиво» и события по-прежнему создаются только для мест из `places.yaml` (раздел 6 не меняется).
- **Еженедельный отчёт Олегу.** Первый удачный прогон в понедельник в 09:00 по Еревану или позже (раз в неделю, `state.discovery.last_report_date`) — одно сообщение в личку Олегу (не в общий чат) со списком мест не из `places.yaml`, у которых ≥3 чекинов за 30 дней и которые ещё не упоминались (`state.discovery.reported`). Если таких нет, сообщение не шлём, но неделю всё равно отмечаем проверенной.
- **Проверка города (4.2, 4.3).** После основных источников Untappd, если остался бюджет страниц: до 3 мест не из `places.yaml` за прогон, у которых ≥2 чекинов за 30 дней и город ещё не известен (сортировка — по числу чекинов), тем же клиентом (тот же бюджет, блокировка Cloudflare останавливает и это). Кандидаты — это места, уже накопленные в `state.venues` к началу прогона (по чекинам с предыдущих прогонов): новое место впервые увиденное в этом же прогоне проверяется городом только со следующего. Со страницы места берём JSON-LD `<script type="application/ld+json">` с `"@type":"Location"` (сам блок может быть объектом или списком объектов — берём первый подходящий, остальные формы markup пропускаем без ошибки): `address.addressLocality`/`address.addressCountry`. Своего `addressCountry` у армянских мест в разметке не встречалось — вместо этого `addressLocality` содержит город и страну без разделителя, например «Yerevan Հայաստան» или «Gyumri Հայաստան»: страна отделяется от города по хвостовому написанию Armenia/Հայաստան, остальное — город. Проект охватывает только Ереван: в еженедельный отчёт и в список `venues` на сайте (раздел 8) попадают места, у которых город — написание Ереван/Yerevan/Երևան; прочие армянские города (Гюмри и т.п.) при этом всё равно получают `country: "Armenia"`, но остаются скрытыми, как и зарубежные места. Место с этой проверкой попадает в `state.venues[<venue_id>]`: `city`, `country`, `location_checked_at`, а также `logo`/`verified`, если страница их отдаёт. Локация считается известной, если заполнено хотя бы одно из `city`/`country` (например, разметка с одним `addressCountry` без `addressLocality`) — тогда прогон не пытается проверить место снова. Ошибка сети/Cloudflare/бюджета останавливает весь шаг без отметки — повтор в следующем прогоне; неожиданная разметка одной страницы (сбой разбора) отмечает только это место проверенным и не прерывает шаг для остальных кандидатов; успешный разбор без определённой локации отмечается и не повторяется 90 дней; известная локация (любая) не перепроверяется вовсе. Места из `places.yaml` показываются всегда, независимо от города.
- **Каноническая ссылка на пиво у чекинов (4.2, 4.3).** `url` строки-чекина берётся из `href` самой ссылки на пиво в HTML чекина (`/b/<slug>/<id>`, тот же вид, что и у строк меню, — открывается в приложении Untappd, а не в браузере), а не собирается как `/beer/<id>`. Если ссылка почему-то без `href` (не должно случаться на реальной странице), остаётся откат на `https://untappd.com/beer/<id>`.
- **Рейтинг пива для чекинов без меню (4.2, 4.3).** В v1 страницы пива не запрашивались (раздел «Чекины» выше). Теперь после основных источников Untappd и вместе с проверкой города, тем же клиентом (тот же бюджет, пауза, остановка при Cloudflare/бюджете) — до 5 пив за прогон, у которых чекин виден на сайте (пара «место + пиво» с чекином не старше 21 дня), нет пары в меню ни в одном месте и либо рейтинга ещё нет в кеше, либо кеш старше 30 дней (сначала самые недавно увиденные). Со страницы пива `https://untappd.com/b/<slug>/<id>` берём рейтинг (`div.caps[data-rating]` в заголовке пива), стиль, крепость и IBU; кладём в `state.beers[beer_key]` (раздел 5). Разбор без результата (изменилась разметка, логин-стена) сохраняет `TAPS_DEBUG_DIR`-дамп страницы (`untappd_beer_<id>`) и всё равно отмечает попытку, чтобы не запрашивать снова каждый прогон. Правила (раздел 6) добавляют эти кэшированные поля в строку чекина, если у неё их ещё нет (меню — приоритетнее); 🔥 в сводке и на сайте показывается и для таких строк по общему правилу `hot_rating`.

## 5. Данные

**`places.yaml`.**
- `places`: `id`, `name`, `kind` (bar / brewpub / shop), источники и их параметры (`untappd_slug` + `untappd_id` для заведения; id пивоварни у brewpub), `enabled`.
- `breweries`: пивоварни из 4.2 (`id`, `name`, `brewery_slug`, `brewery_id`, `list_enabled`). Это не места: на сайт они не выводятся.
- `settings`: `preview_digests: 2`, `digest_time: "17:00"` (должно быть раньше вечернего cron), `digest_max_lines: 15`, `hot_rating: 3.75`, `untappd_daily_pages: 30`.

**«Замечено» (Sighting):** `place_id`, `source`, `beer_key`, `untappd_beer_id?`, `shop_item_id?`, `title` (как в источнике), `name`, `brewery?`, `style?`, `abv?`, `ibu?`, `rating?`, `price_amd?`, `volume?`, `container?`, `serving?`, `in_stock?`, `menu_id?`, `seen_at`, `url`.

**Ключи пива.**
- `u:<id Untappd>`, если id известен.
- `n:<нормализованное название>` в остальных случаях.
  - **Исходный текст:** у Untappd `пивоварня + " " + название`, у магазинов латинское название из листинга (Beer City и Parma `/en/`, Yerevan City `nameEn`).
  - **Нормализация:**
    - строчные буквы;
    - убираем слова типа (beer, draught, beer drink), объём, тару (can, bottle, keg), кавычки, пунктуацию, юридические и служебные хвосты пивоварен (brewery, brewing, brauerei, privatbrauerei, llc, gmbh, co);
    - схлопываем пробелы;
    - слова цвета (light, dark) сохраняются.
- **У каждого `u:`-ключа в `beers` хранится и его `n:`-ключ.** Это нужно для сравнения с магазинами и на случай, если Untappd сменит id.
- **У магазинов ключ фиксируется при первом появлении номера товара** (`shop_items[place][item_id] = beer_key`) и потом не пересчитывается.
- **Parma и цвет.** Если у нового кода нет слова цвета, а у Parma уже есть ключ, который совпадает с ним плюс слово цвета, новый код приписывается к этому ключу.
- **Совпадение магазинов с Untappd приблизительное.** Ошибка влияет только на пометку ⭐, лишних строк она не создаёт. Правится разделами `aliases` и `brewery_aliases` в `corrections.yaml`.

**`state.json`.**
- `pairs[place_id][beer_key]`:
  - `first_seen`;
  - `last_seen`;
  - `event_at` — момент, когда пара стала событием. Обычно это `first_seen`. У товара, впервые замеченного «нет в наличии», это первый прогон, где он в наличии; до этого поле пустое, и пара событием не считается;
  - `star` — пометка ⭐. Вычисляется один раз при создании пары по `beers` до записей этого прогона. Сводка и сайт читают только это поле;
  - `notified_at` — время объявления, `"baseline"` или `"suppressed"`;
  - `last_in_result` — есть ли пара в последнем удачном (полном) результате;
  - `in_stock`;
  - последние поля для показа.
- `beers[beer_key]`: `first_seen_city`, `n_key`. v1.1 §4: также `rating`, `style`, `abv`, `ibu`, `rating_at` — кеш со страницы пива для чекинов без меню (не удаляется, обновляется раз в ≥30 дней).
- `brewery_new[beer_key]` — события 🏭: `brewery_id`, `found_at`, `star`, `notified_at`. `max_beer_id` пивоварни сдвигается в том же изменении, где создаётся запись.
- `shop_items[place_id][item_id]` — `beer_key`.
- `sources[<ключ>]`, где ключ — `"<source>:<place_id>"` для 4.1, 4.3–4.6 и `"untappd_brewery:<brewery_id>"` для 4.2 (чекины и список сортов):
  - `baseline_done`, `last_ok`, `last_full`, `last_count`;
  - `fail_streak`, `trip_streak`, `last_trip_keys`;
  - `seen_menu_ids`, `max_beer_id` (для 🏭).
- `untappd`: `last_attempt`, `pages_today`, `pages_date`, `brewery_list_cursor`.
- `digest`: `last_sent_date` (дата по Еревану), `last_sent_at`, `sent_count`.
- `alerts` — открытые предупреждения (тип + источник + хеш), чтобы слать одно на серию.
- `corrections_snapshot` — последняя удачно прочитанная версия `corrections.yaml`.
- `announced_manual` — id уже объявленных записей «со слов».
- `started_at`.

**Размер.**
- Пары, которых не видели больше 180 дней, удаляются, но только если у их «источника + места» был удачный прогон за последние 30 дней. У источника, который долго не отвечает, пары не удаляются.
- Записи `beers` не удаляются, иначе старое пиво снова станет «возможно, впервые». Это тысячи коротких строк, десятки килобайт.
- Всё вместе меньше 1 МБ. Файл перезаписывается и не растёт.

## 6. События и правила

| Значок | Событие | Когда |
|---|---|---|
| 🆕 | новое в месте | появилась пара «место + пиво» с `notified_at` = пусто (правила ниже) |
| ⭐ | возможно, впервые в Ереване | пометка на строке 🆕/🏭/👀/✍️/🛒: ни `u:`-ключа, ни его `n:`-ключа нет в `beers` |
| 🏭 | новый сорт местной пивоварни | раздел 4.2 |
| 🔥 | пометка рейтинга | рейтинг Untappd от `hot_rating` (3.75); только из меню, не из чекинов; не фильтр |

**Тихий первый прогон.** Всё найденное запоминается с `notified_at = "baseline"`, в том числе товары «нет в наличии». Событий нет. Срабатывает:
- при первом удачном прогоне по ключу `sources` (раздел 5), в том числе для нового места в старом источнике, смены источника у места или переименования id;
- для нового места: пока не прошёл первый удачный прогон по его собственному источнику, всё, что о нём приходит из других источников (например, чекины со страниц пивоварен 4.2), тоже пишется молча;
- для вкладки меню (`menu_id`), которой не было в прошлом удачном прогоне;
- при потере `state.json`;
- при первом удачном прогоне после того, как `last_ok` устарел больше чем на 3 суток (долгий сбой, восстановленное старое состояние). Для списка сортов пивоварни, который обходят раз в 4–8 дней, порог — 30 суток;
- когда предохранитель принимает результат (раздел 10).

Источник «со слов» тихого первого прогона не проходит.

**Когда событие 🆕 не создаётся:**
- у места уже есть пара с тем же `n:`-ключом (Untappd сменил id);
- пиво не прошло фильтр магазинов, попало в `not_craft` или `hide`. Тогда пара записывается с `notified_at = "suppressed"`. Если потом снять фильтр или `hide`, событий не будет.

**В `beers` пишем** только наблюдения, прошедшие правила этого раздела и привязанные к месту из `places.yaml` (товар «нет в наличии» тоже), и новые сорта 🏭. Отброшенные чекины и отфильтрованные товары `beers` не трогают.

**Не события:**
- пиво пропало или вернулось;
- изменилась цена;
- изменилось наличие;
- добавили склейку в `aliases` (раздел 9).

**Чекин 👀 становится событием**, только если выполнено всё сразу:
- место есть в `places.yaml`, и у него нет источника-меню (4.1 или 4.4). Чекины в местах с меню игнорируются;
- подача Draft, либо подача пустая, а место — бар самой пивоварни этого пива (Dors в Dors);
- это не «Untappd at Home»;
- чекин моложе 7 дней;
- пары «место + пиво» ещё нет; хватает одного чекина.

**Со слов ✍️.**
- Событие даёт запись с `date` не старше 3 дней, если её id (место + date + by) ещё не объявлялся.
- Исправление названия пива повторного объявления не даёт. Изменение места, даты или автора делает запись новой: такие правки в уже объявленной записи не нужны.
- Предохранитель на этот источник не действует.

**Магазины 🛒.** Пара магазина, которая ни разу не была в наличии, событием не является. Если товар впервые замечен после тихого первого прогона с отметкой «нет в наличии», событие появляется в прогоне, где он впервые оказался в наличии (`event_at`).

### v1.1

- **Чекины в магазинах (4.3).** Для мест с `kind: shop` (например, Houl) подача не важна: Bottle, Can, пустая подача и Draft — все считаются, в отличие от баров/пабов, где действуют правила выше. В сводке такие чекины идут в блок 🛒 «Магазины», на сайте — во вкладку «Магазины», со значком 👀 «видели N дней назад», как обычный чекин.
- **🔥 у чекинов без меню.** Строка «в таблице 🔥» больше не только из меню: чекин, для которого рейтинг подставлен из другой пары меню или из кеша `state.beers` (раздел 4, «Рейтинг пива для чекинов без меню»), тоже получает 🔥 при рейтинге ≥ `hot_rating`, иначе показывается просто числом — как в меню.

## 7. Сводка в Telegram

**Неотправленные события:** пары с `event_at` и пустым `notified_at`, записи `brewery_new` с пустым `notified_at`, записи «со слов», которых нет в `announced_manual`. Время события — `event_at` / `found_at` / `date`.

**Устаревшие события отбрасываются первыми**, до проверки «пора ли». Событиям старше 3 дней ставится `notified_at` без отправки, и они остаются только на сайте.

**Когда.** Сводку пора слать, если выполнено всё сразу:
- по Еревану сейчас 09:00–23:00;
- `digest.last_sent_date` ≠ сегодня, и с `last_sent_at` прошло не меньше 20 часов;
- после отбрасывания устаревших остались неотправленные события;
- сейчас не раньше `digest_time` (17:00), **или** самое старое неотправленное событие создано раньше вчерашних 17:00.

События, найденные сегодня до 17:00, ждут вечернего прогона. Если вечерний прогон пропал, сводка уйдёт утренним прогоном следующего дня. Пустую сводку не шлём и отметку `last_sent_*` не ставим.

**Протокол отправки:**
1. Сводку собираем из всех неотправленных событий.
2. В `state.json` одним изменением пишем `last_sent_date`, `last_sent_at`, `sent_count + 1`, `notified_at` у всех пар и записей `brewery_new` этой сводки (включая спрятанные за «…и ещё N») и добавляем id записей «со слов» в `announced_manual`.
3. `commit` + `git push`.
   - Если push отклонён, делаем `pull --rebase`. Это допустимо, только если в новых удалённых коммитах `state.json` не менялся: например, Олег правил `corrections.yaml`. Затем push снова, до 3 попыток.
   - `state.json` никогда не сливаем автоматически и не делаем force-push.
   - Если push так и не прошёл, сообщение не отправляем, и прогон завершается с ошибкой.
4. `sendMessage` с таймаутом 30 с.
   - `ok:true` — готово.
   - `ok:false` с 429: ждём `retry_after`, один повтор.
   - `ok:false` с 400/403 (или 429 после повтора): сообщение точно не принято. Откатываем все поля шага 2, делаем commit + push и одно предупреждение Олегу на серию.
   - Таймаут, обрыв, 5xx или непонятный ответ: считаем, что сообщение ушло. Отметку не откатываем, Олегу уходит «сводка, возможно, не дошла».
   - `migrate_to_chat_id`: как 400, Олегу уходит новый id чата.

**Пробные сводки.** Первые `preview_digests` (2) сводки уходят в личку Олега (`TELEGRAM_ADMIN_CHAT_ID`), дальше в чат (`TELEGRAM_CHAT_ID`). Пробная сводка во всём ведёт себя как обычная: те же отметки, тот же откат.

### Гарантии против спама

1. **В чат не больше одного сообщения в сутки** и не чаще раза в 20 часов. Ручной перезапуск, повтор прогона, второй cron и прогон с Мака ничего лишнего не отправят. Прогоны не идут одновременно: `concurrency`, checkout с вершины `main`, отметка сохраняется до отправки.
2. **Лучше пропустить сводку, чем прислать её дважды.** Отправляем только после удачного push отметки. Откат делается только при явном отказе Telegram.
3. **Ни одно событие не объявляется дважды.** `notified_at` ставится всем событиям сводки, включая «…и ещё N».
4. **Не больше 15 строк с пивом**, остальное на сайте.
5. **Уже известное пиво не превращается в новинки.** Тихий первый прогон срабатывает для нового источника, места, вкладки меню и после потери или устаревания состояния, в том числе для товаров «нет в наличии». Добавление склейки, снятие фильтра или `hide` событий не дают.
6. **Массовая смена меню не превращается в сводку.** Её останавливает предохранитель (раздел 10).
7. **Битый `corrections.yaml` не даёт ложных новинок** (раздел 9).
8. **Служебные сообщения идут только в личку Олега**, одно на серию сбоев. В чате бот ничего не отвечает и ничего не читает.

**Формат.**
- HTML-разметка; каждая подставляемая строка проходит `html.escape`.
- Беззвучно (`disable_notification`), без превью ссылок, одна кнопка-ссылка «Открыть список».
- Порядок:
  - 🍻 БАРЫ:
    - места с ✅: заголовок места и строки, внутри места сначала ⭐;
    - затем общие блоки 🏭, 👀, ✍️, где в каждой строке «в <место>»;
  - 🛒 МАГАЗИНЫ: заголовок магазина и строки.
- Пиво в нескольких местах одного блока выводится один раз, под первым местом, с припиской «+ ещё в X, Y».
- Лимит считает только строки с пивом (•). Строки сверх лимита отрезаются с конца, дальше «…и ещё N — на сайте».
- Подпись: «⭐ — возможно, впервые в Ереване (с тех пор, как следим, с ДД.ММ)», где ДД.ММ = `started_at` по Еревану.

Пример:

```

• ⭐ Zagovor — Black Sails · Imperial Stout 11% 🔥4.12

🏭 Новые сорта пивоварен

• Dors — Smoked Porter · в Dors, разлив, видели 2 дня назад
✍️ Со слов

Beer City
```

## 8. Сайт

- **Основа.** Одна статичная страница `site/index.html` без сборки, в основе страница знакомого. Она читает `data.json`.
- **Вкладки и фильтры:**
  - вкладки 🍻 Бары | 🛒 Магазины;
  - переключатель «🆕 только новинки за 7 дней»;
  - сортировка по новизне (по умолчанию), рейтингу или крепости;
  - кнопки с местами и поиск по названию, стилю и пивоварне.
- **Какие строки видны:**
  - ✅ и 🛒 — только если пиво есть в последнем удачном результате своего «источника + места», а у магазина ещё и в наличии. Для Beer City это последний полный обход плюс номера, добавленные частичными прогонами после него (наличие берётся из карточки);
  - 👀 — 21 день после последнего чекина, с подписью «видели N дней назад»;
  - ✍️ — 14 дней от `date`.
- **Строка = место + пиво.** В строке:
  - название со ссылкой на Untappd или страницу товара;
  - пивоварня, стиль, крепость, IBU;
  - рейтинг, цена;
  - источник;
  - «с ДД.ММ».
- **Значки 🆕 и ⭐ на сайте** ставятся только у пар, которые дали событие (`notified_at` — дата, а не `baseline` или `suppressed`), и только 7 дней.
- **Карточка места:** «меню обновлено N дней назад» (для Untappd), «проверено сегодня в ЧЧ:ММ» или «⚠️ не удалось проверить N дней».
- **Свежесть:** общее «обновлено N ч назад». Если данным больше 36 часов, сверху жёлтая плашка «данные устарели».
- **Раскладка:** на телефоне карточки, на компьютере таблица.
- **Подвал:** источники данных со ссылками, расшифровка значков, благодарность проекту знакомого, «нашли ошибку — напишите Олегу».
- **Адрес** `https://olegbeers.github.io/yerevan/`: аккаунт GitHub `OlegBeers`, по репозиторию на город (`yerevan`, дальше другие города). Локальная папка проекта остаётся `yerevan-taps`. История данных в git не хранится.

### v1.1

- **Логотип и «Verified» у мест и в списке мест.** `places[]` в `data.json` получает `logo`, `verified`, `untappd_url` (все — `null`/`false`, если места нет на Untappd или его страница ещё не собиралась).
- **Вкладка «📍 Все места».** Новый список `venues[]` в `data.json`: каждое место, увиденное в чекинах хотя бы раз за последние 30 дней (сортировка — по числу чекинов, затем по имени), с числом чекинов, датой последнего и отметкой «в списке» (`tracked`), если оно уже есть в `places.yaml`. Место не из `places.yaml` попадает в список только когда проверка города (раздел 4) определила его как армянское; непроверенные и зарубежные места скрыты, пока проверка не подтвердит Армению.

## 9. Файл правок `corrections.yaml`

Друзья пишут Олегу, Олег правит файл в браузере на GitHub или просит Claude. Следующий прогон подхватывает изменения.

```yaml
sightings:                       # ✍️ со слов
  - place: tap-station
    brewery: "379"
    beer: "Hazy Pale"            # или untappd: 1234567
    by: Аня
    date: 2026-09-24
hide:                            # «этого уже нет» или мусор
  - place: gargoyle
    beer: u:3539672
aliases:                         # одно и то же пиво из разных источников
  "n:konix bronx": u:3539672
brewery_aliases:                 # написания пивоварен
  "v engelman": "volfas engelman"
not_craft:                       # не показывать в магазинах (начальный список — раздел 4.6)
  - Kilikia
```

- **Склейки применяются везде.**
  - При загрузке состояния переписываются ключи в `pairs`, `beers`, `brewery_new` и значения `shop_items`. Совпавшие записи сливаются: берётся самый ранний `first_seen` / `first_seen_city` и любая непустая `notified_at`.
  - Ключ каждого нового наблюдения переписывается до слияния с состоянием.
  - Добавление склейки никогда не создаёт событий, ни в этом прогоне, ни в следующих.
- **Если файл не читается целиком** (битый YAML), прогон использует `corrections_snapshot` из `state.json`. Если снимка нет, прогон останавливается: ничего не пишет и не шлёт. Олегу одно предупреждение.
- **Ошибочная отдельная запись** (неизвестное место, нет даты) пропускается. Олегу одно предупреждение на каждую новую ошибку: хеш хранится в `alerts`.

## 10. Сбои и вежливость

**Предохранитель на пару «источник + место».** Результат отбрасывается, если:
- запрос упал;
- обнаружена проверка Cloudflare: статус 403, заголовок `cf-mitigated` или в HTML `_cf_chl_opt`, `/cdn-cgi/challenge-platform/h/`, `<title>Just a moment` (без учёта регистра). Голого `challenge-platform` мало: скрипт `/cdn-cgi/challenge-platform/scripts/...` Cloudflare вставляет и в обычные страницы. Заголовок страницы — лишь один из признаков и не единственный: у знакомого проверка искала только английское «Just a moment» и пропускала испанскую страницу;
- пришло 0 позиций (кроме «со слов»);
- для меню и магазинов, у которых в прошлом удачном (полном) результате было 20 позиций и больше:
  - позиций стало меньше половины;
  - больше половины позиций — ключи, которых нет в `pairs` этого места. Для Beer City обе проверки делаются только на полном обходе и сравниваются с прошлым полным. Частичный прогон проверяется только на ошибку и пустую первую страницу;
- для списка сортов пивоварни: больше 5 новых id за раз.

**Что тогда происходит:**
- на сайте остаются последние хорошие данные с пометкой «⚠️ не проверено N дней»;
- событий из этого источника нет;
- Олегу одно предупреждение на серию;
- остальные источники работают дальше. Это урок сайта знакомого: 20 августа там три бара из четырёх вернули 0 позиций и молча затёрли данные.

**Выход из предохранителя.**
- Если проверка по количеству или доле новых срабатывает 3 прогона подряд, а результаты совпадают между собой на 80% и больше, это настоящая перемена (перестроили меню). Результат принимается как тихий первый прогон, Олегу уходит «принял новое меню X молча».
- Ошибки запроса и Cloudflare так не принимаются.

**Вежливость к Untappd.**
- `untappd.last_attempt` — время последнего сбора, который получил ответы от Untappd (успех или Cloudflare). Сетевая ошибка не считается.
- Следующий сбор — не раньше `last_attempt + 20 ч`. Пропуск по этому лимиту не сбой: `fail_streak` и `last_ok` не меняются, пометки ⚠️ нет.
- Жёсткий бюджет `untappd_daily_pages` (30) страниц за дату по Еревану, счётчик в `untappd.pages_today`.
- Порядок сбора:
  1. меню (4.1), около 4 страниц;
  2. пивоварни (4.2), 8;
  3. бары (4.3), 11;
  4. 1–2 списка сортов.
- Когда бюджет кончился, оставшиеся места пропускаются без статуса сбоя.
- Паузы 4–6 с между страницами. После сетевой ошибки один повтор через 10 с.
- **Первая же проверка Cloudflare на любой странице** останавливает весь сбор Untappd в этом прогоне: все Untappd-источники получают статус сбоя, Олегу одно предупреждение. Магазины работают дальше.

**Прочее:**
- **Упал весь прогон:** GitHub присылает письмо, на сайте через 36 часов появляется плашка «данные устарели». Если так и не починилось, Олег запускает прогон вручную или с Мака.
- **Никакой растущей истории в git.** Второй урок знакомого: его файл истории упёрся в лимит GitHub в 100 МБ, и публикация встала.

## 11. Тестирование

**Парсеры — на сохранённых настоящих страницах**, сети в тестах нет:
- Untappd:
  - меню Gargoyle и Beatles (копии из веб-архива 2024–2026);
  - страница пивоварни Dargett (архив);
  - лента чекинов заведения без меню: Craft Story (копия 2025-01, уже неверифицированное, около 20 чекинов) и Vertigo (копия 2025-10, без меню, около 6 чекинов). Если их разметка окажется не такой, как у нынешних страниц, живую страницу сохраняем на первом ручном прогоне;
  - список сортов пивоварни — сохраняем на первом ручном прогоне;
- Beer City: листинг XHR и страница товара;
- buy.am: `__NEXT_DATA__`;
- Parma: 4 страницы листинга и страница товара;
- Yerevan City: GetByCategory и Search.

**Юнит-тесты правил:**
- тихий первый прогон: новый источник, новое место в старом источнике, новая вкладка меню, потеря состояния, `last_ok` старше 3 суток; товары «нет в наличии» в тихом первом прогоне потом не объявляются;
- 🆕, ⭐ (в том числе по `n:`-ключу, смена id Untappd), 🏭 (только id больше максимума), 🔥;
- фильтр чекинов: бутылка, «at home», пустая подача в баре пивоварни, чекин старше 7 дней, чекин в месте с меню;
- фильтр магазинов: стоп-лист целым словом («bud» ≠ «Budvar»), стиль сильнее стоп-листа, радлер по вкусу, безалкогольное;
- склейка по `aliases` не создаёт событий, в том числе три прогона подряд для товара магазина со склеенным ключом; снятие фильтра или `hide` не создаёт событий;
- ⭐ события, найденного утром, сохраняется в вечерней сводке (`star`);
- список сортов, обойдённый снова через 6 дней, даёт 🏭 для id выше максимума;
- новое место: чекины о нём со страниц пивоварен до его первого прогона пишутся молча;
- товар магазина, ни разу не бывший в наличии, не запускает утреннюю сводку и не устаревает; событие появляется, когда он в наличии;
- остались только устаревшие события — сообщения нет, отметки `last_sent_*` нет;
- Parma: код без цвета приписывается к ключу с цветом;
- смена цены и наличия не даёт события;
- все срабатывания предохранителя и выход из него после 3 одинаковых прогонов; частичный прогон Beer City не запускает предохранитель;
- первая проверка Cloudflare останавливает весь Untappd; лимит 20 часов и бюджет 30 страниц;
- «со слов»: событие при `date` ≤ 3 дней, исправление названия не даёт повтора;
- удаление пар старше 180 дней, но не у долго молчащего источника;
- битый `corrections.yaml`: работа по снимку, а без снимка остановка.

**Гарантии против спама (раздел 7):**
- сводка в 18:17; пропущенный вечер → утро; утро не шлёт сегодняшние события; между сводками не меньше 20 часов;
- два прогона с одного базового коммита: шлёт только первый (push второго отклонён);
- push не прошёл — ничего не отправлено;
- таймаут Telegram не откатывает отметку; 400/403 откатывает; `notified_at` ставится и событиям из «…и ещё N»;
- первые 2 сводки уходят в личку, третья в чат;
- служебные сообщения только в `TELEGRAM_ADMIN_CHAT_ID`, одно на серию;
- `html.escape` для названий с `&`, `<`, `>`.

**Снимок текста сводки** для фиксированного набора событий.

**`--dry-run`:** печатает сводку и `data.json`, ничего не отправляет и не коммитит.

**Перед включением расписания:**
